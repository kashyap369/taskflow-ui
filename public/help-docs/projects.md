## What a project is

A container for related work - a product launch, a client engagement, a quarter of maintenance. Every task belongs to exactly one project.

A project carries its own name, date range and status. Those are for planning and reporting; they do not constrain the tasks inside it. Moving a project's dates does **not** move its tasks' dates.

## Creating one

A name and a date range is enough. You can start adding tasks immediately and adjust everything later.

## Importing a plan

If the plan already exists elsewhere, use **Import project plan** rather than retyping it. Tasks and their dates come across together.

## Inside a project

Opening a project shows its tasks, its progress and the people working on it. Tasks added from inside a project are filed under it automatically - usually the fastest way to build one out.

## What a project connects to

| Connects to | How |
|---|---|
| **Tasks** | Every task lives in one project |
| **Teams** | Teams organise who works on it |
| **Calendar** | Dated tasks in the project appear there |
| **Reports** | Project reports measure completion and logged time |

## Deleting

Deleting a project removes the work filed under it. If you only want it out of the way, change its status instead.
